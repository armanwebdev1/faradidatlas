# Payload CMS Admin Panel Upgrade Plan

## Scope

Upgrade the Faradid Atlas Payload CMS admin panel from near-stock to premium enterprise-grade while keeping the public website completely untouched.

## What Already Exists (Do NOT Modify)

- Custom Dashboard (`src/admin/components/CustomDashboard.tsx`) — stat cards, recent edits, quick links
- Content localization (en/fa/ar) with fallback
- Draft versions on 7 of 10 collections
- Vercel Blob storage for media
- Basic draft preview route (`app/api/preview/route.ts`)

## Phase 6: Admin i18n — Persian/English Interface

**Goal:** Make the admin interface switchable between Persian and English, independent of content locale.

### Files to Create

1. **`src/admin/i18n/en.ts`** (NEW) — English admin translations
2. **`src/admin/i18n/fa.ts`** (NEW) — Persian admin translations
3. **`src/admin/i18n/index.ts`** (NEW) — Translation utility
4. **`src/admin/components/LanguageSwitcher.tsx`** (NEW) — Admin language toggle component

### Files to Modify

1. **`payload.config.ts`** — Add `admin.components` overrides for translated labels
2. **`src/admin/components/CustomDashboard.tsx`** — Use translated strings

Implementation approach: Use Payload's built-in admin localization support. Payload 3.x supports `admin.components` for Nav, and we can inject a language switcher. The admin labels (collection names, field labels, button text) can be customized via Payload's field-level `admin.label` and collection-level `admin.label` properties, or by using the `@payloadcms/translations` package approach with custom overrides.

Given the complexity of fully translating every Payload admin string, a pragmatic approach:
- Translate the custom dashboard content
- Translate sidebar group labels via admin config
- Add a language switcher that affects our custom components
- Use Payload's `admin.description` with localized descriptions

   - A custom field (select: draft/review/published/archived)

## Phase 9: Role-Based Access Control (3 Roles)

### Current State
- Users collection has 2 roles: `admin` and `editor`
- All collections have `read: () => true` (public read)
- No write access controls defined — only authenticated admin users can write

### Role Definitions

#### Super Admin (`super-admin`)
Full access to everything.
- All collections: full CRUD
- All globals: full read/write
- User management: create, edit, delete users, assign any role
- Site settings, redirects, translations: full access

#### Company Admin (`company-admin`)
Can manage all content and company pages, but NOT system settings or user management.
- Content collections (products, categories, brands, blog, jobs, FAQs, downloads, certificates, media): full CRUD
- Company globals (homepage, company-info, contact-info, careers-info, navigation): full read/write
- Site settings, redirects, translations: read-only
- Users: no access

#### Editor (`editor`)
Can edit existing content, limited create ability.
- Content collections (blog-posts, jobs, faqs): create, edit, delete
- Products, categories, brands, downloads, certificates: edit only (no create/delete)
- Media: upload and edit
- Company globals: read-only
- Site settings, redirects, translations, users: no access

### Files to Create

1. **`src/access/isRole.ts`** (NEW) — Role-checking helper:
```ts
import type { Access } from 'payload'

export const isRole = (...roles: string[]): Access => ({ req }) => {
  const user = req.user
  if (!user) return false
  return roles.includes(user.role)
}
```

### Files to Modify

1. **`src/collections/Users.ts`**
   - Update `role` field options: `super-admin`, `company-admin`, `editor`
   - Add access: only super-admin can create/edit/delete users
   - Only super-admin can assign the super-admin role

2. **Catalog collections** (Products, Categories, ProductBrands, Downloads, Certificates):
   - `create`: company-admin, super-admin
   - `update`: company-admin, super-admin, editor
   - `delete`: company-admin, super-admin

3. **Content collections** (BlogPosts, Jobs, FAQs):
   - `create`: company-admin, super-admin, editor
   - `update`: company-admin, super-admin, editor
   - `delete`: company-admin, super-admin, editor

4. **Media**:
   - `create`: company-admin, super-admin, editor
   - `update`: company-admin, super-admin, editor
   - `delete`: company-admin, super-admin

5. **Company globals** (Homepage, CompanyInfo, ContactInfo, CareersInfo, Navigation):
   - `update`: company-admin, super-admin

6. **Settings globals** (SiteSettings, Redirects, Translations):
   - `update`: super-admin only
