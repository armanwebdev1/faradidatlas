# Migration Plan: Supabase → Neon PostgreSQL

## Overview

Migrate the Faradid Atlas database from Supabase hosted PostgreSQL to Neon PostgreSQL. This is a clean, low-risk migration because:

- **No Supabase SDK** is used — only the PostgreSQL connection string in `.env`
- **No Supabase-specific features** (Auth, Storage, Realtime) — all handled by Payload CMS + Vercel Blob
- **Single connection point** — only `DATABASE_URL` in `.env` needs to change
- **Standard PostgreSQL** via `@payloadcms/db-postgres` adapter

---

## Prerequisites

- Neon account and project created (confirmed)
- `pg_dump` and `psql`/`pg_restore` available locally (part of PostgreSQL client tools)
- Current Supabase connection string (in `.env` line 16)
- Neon connection string (from Neon console → Connection Details)

## Step 1: Export Data from Supabase (pg_dump)

Dump the full database schema + data from Supabase:

```bash
pg_dump -Fc -v -h aws-1-ap-northeast-2.pooler.supabase.com \
  -p 5432 -U postgres.pegpjlcbdylkvlqpqbtz \
  -d postgres -f supabase_dump.dump
```

**What this captures:**
- All tables (products, categories, blog_posts, faqs, jobs, media, users, etc.)
- All enums (locale types, product types, status enums, etc.)
- All data (CMS content, user accounts, locale variants)
- Indexes, constraints, sequences

**Note:** You'll be prompted for the password (`Arman1132Arina`).

**Alternative** (if `pg_dump` isn't available):
```bash
# Using Neon's built-in migration import from the Neon console
# Or use the SQL dump format:
pg_dump -h aws-1-ap-northeast-2.pooler.supabase.com \
  -p 5432 -U postgres.pegpjlcbdylkvlqpqbtz \
  -d postgres > supabase_dump.sql
```

---

## Step 2: Restore Data to Neon

Restore the dump into your Neon database:

```bash
pg_restore -v -h <your-neon-host>.neon.tech \
  -p 5432 -U <your-neon-user>.neondbowner \
  -d <your-neon-database> \
  --no-owner --no-privileges \
  supabase_dump.dump
```

**Neon connection details** (from Neon Console → Connection Details → PSQL):
- Host: `<project-id>.cloud.neon.tech` (or use the pooler endpoint)
- Port: `5432`
- Database: `neondb` (or your chosen name)
- User: `<your-neon-user>`
- Password: (from Neon console)

**Important flags:**
- `--no-owner`: Avoids ownership issues between Supabase and Neon
- `--no-privileges`: Skips role grants that may not exist on Neon

**If using SQL dump format:**
```bash
psql -h <your-neon-host>.neon.tech -p 5432 \
  -U <your-neon-user>.neondbowner -d <your-neon-database> \
  -f supabase_dump.sql
```

## Step 3: Update Environment Variable

Update `DATABASE_URL` in `.env` (line 16) to point to Neon:

**Before (Supabase):**
```
DATABASE_URL=postgresql://postgres.pegpjlcbdylkvlqpqbtz:Arman1132Arina@aws-1-ap-northeast-2.pooler.supabase.com:5432/postgres
```

**After (Neon):**
```
DATABASE_URL=postgresql://<user>:<password>@<host>.neon.tech:5432/<database>?sslmode=require
```

**Neon requires SSL** — append `?sslmode=require` to the connection string.

## Step 6: Update Payload Connection Pool Settings (Optional)

Neon's connection model differs from Supabase. Consider adjusting pool settings in `payload.config.ts` (lines 66-76):

```typescript
db: postgresAdapter({
    pool: {
      connectionString: process.env.DATABASE_URL || "",
      max: 3,           // Keep conservative for Neon's connection limits
      min: 0,
      idleTimeoutMillis: 5000,
      connectionTimeoutMillis: 10000,
      keepAlive: true,
      keepAliveInitialDelayMillis: 0,
    },
}),
```

**Neon considerations:**
- Neon's free tier has connection limits (~100 concurrent connections)
- Neon supports connection pooling (pooled endpoint) — use it for production
- The current pool settings (`max: 3`) are already conservative and should work fine

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Data loss during migration | Low | High | pg_dump is reliable; keep Supabase as backup |
| Schema incompatibility | Very Low | High | Both are PostgreSQL; Payload uses standard PG features |
| SSL connection issues | Medium | Low | Neon requires `sslmode=require`; already in plan |
| Connection pool exhaustion | Low | Medium | Current `max: 3` is conservative; Neon supports pooling |
| Performance differences | Low | Low | Neon is serverless PG; may have cold start differences |
