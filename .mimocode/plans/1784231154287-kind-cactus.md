# Payload Admin UI Bilingual i18n (EN + FA) Implementation Plan

## Key Discovery

**Payload CMS v3 already provides official Persian (`fa`) translations** via `@payloadcms/translations/languages/fa`. The task description states "Payload does not currently provide an official Persian language pack" — this is incorrect. We will use the official translations rather than creating custom ones.

## Implementation Steps

### Step 1: Install `@payloadcms/translations`

```bash
pnpm add @payloadcms/translations
```

### Step 2: Add `i18n` config to `payload.config.ts`

Add the `i18n` key to the `buildConfig()` call, using official EN + official FA translations:

```ts
import { en } from '@payloadcms/translations/languages/en'
import { fa } from '@payloadcms/translations/languages/fa'

// Inside buildConfig():
i18n: {
  fallbackLanguage: 'en',
  supportedLanguages: { en, fa },
},
```

**This is the core change.** It:
- Enables the official Payload admin UI language switcher
- Translates ALL built-in Payload UI strings (buttons, labels, validation messages, error messages, etc.)
- Persists language preference per user via Payload's built-in user preferences system
- Automatically detects RTL for `fa`

### Step 3: Localize Collection & Global Labels

Add bilingual labels to all collections and globals using Payload's official project translations pattern:

```ts
labels: {
  singular: { en: 'Product', fa: 'محصول' },
  plural: { en: 'Products', fa: 'محصولات' },
},
admin: {
  group: { en: 'Catalog', fa: 'کاتالوگ' },
  description: { en: '...', fa: '...' },
},
```

### Step 4: Add RTL CSS for Persian Admin

Add RTL support rules to `app/(payload)/custom.scss`:

```scss
/* RTL Support for Persian Admin */
[dir="rtl"] {
  .payload-sidebar { direction: rtl; }
  .list-header { direction: rtl; }
  .edit-view { direction: rtl; }
  // ... other admin containers
}
```

Payload v3 automatically sets `dir="rtl"` on the admin body when the user's language is RTL. We need CSS rules that respond to this.

### Step 5: Update Custom Admin Components (Minimal Changes)

The custom components (`CustomDashboard.tsx`, `GlobalSearch.tsx`, `TranslationStatus.tsx`, `LanguageSwitcher.tsx`) use their own `localStorage`-based language system (`admin-lang`). After implementing the official Payload i18n:

- The official Payload language switcher will appear in account settings
- The existing custom `LanguageSwitcher` in the sidebar can remain as a convenience toggle, but should be kept in sync or eventually simplified
- The `CustomDashboard.tsx` uses its own translation keys — these are separate from Payload's built-in UI strings and can continue to work alongside the official i18n

**Decision: Keep the custom admin translation system** (`src/admin/i18n.ts`) for the custom dashboard and components. The official Payload i18n handles the built-in UI; the custom system handles project-specific dashboard strings. No conflict — they operate independently.

### Step 6: Verify User Language Preference

Payload v3 stores per-user language preferences automatically when `i18n` is configured. Users can change it in their account settings. Verify this works after implementation.
