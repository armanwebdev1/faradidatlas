# Plan: Fix and Run Seed Scripts

## Architecture

The new codebase uses **Payload CMS** with PostgreSQL. Data seeding works in two steps:

1. **Schema migration** (`npm run payload:migrate`) — creates/updates database tables
2. **Data seeding** (`npm run migrate`) — populates tables via Payload's API

The `scripts/migrate.ts` orchestrator calls these modules in order:
- `migrate-products.ts` → categories, brands, products
- `migrate-faqs.ts` → FAQ items
- `migrate-jobs.ts` → job postings
- `migrate-translations.ts` → i18n translations
- `migrate-media.ts` → product images

All of these properly load `.env` via `@next/env` and use Payload's API — no hardcoded credentials.

## What You Need to Do

### Step 1: Check your `.env` file

Your `.env` must contain these variables:

```
DATABASE_URL=postgresql://user:password@host:port/dbname?sslmode=require
PAYLOAD_SECRET=your-secret-key
BLOB_READ_WRITE_TOKEN=your-vercel-blob-token  (optional, for media uploads)
```

**Do you have a `.env` file with a valid `DATABASE_URL`?** If your database was migrated to a new location, you need the new connection string.

### Step 2: Run schema migration

```bash
npm run payload:migrate
```

This creates all the CMS tables in your database.

### Step 3: Seed the data

```bash
npm run migrate
```

This populates the tables with all content (products, FAQs, jobs, translations, media).
